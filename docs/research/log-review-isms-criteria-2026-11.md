# 월간 로그 검토(Log Review) 기준 조사: ISMS-P·안전성 확보조치 기준·업계 표준

- 조사일: 2026-11-18
- 결정: [ADR-0015](../adr/0015-log-review-report-drafted-by-host-audit.md). 용어는 `CONTEXT.md`의 Log Review, Log Review Report, Security Policy Review.
- 회사 내부 문서(로그 관련 업무지침, 로그·보안정책 검토결과 대장, 백업 주기 검토대장)는 저장소 밖에 있고, 여기에는 주기·항목 구조만 옮긴다. 문서 번호와 회사 기준·표준의 차이는 비공개 노트에 있다.

## 확인하지 못한 것

- KISA 사이트가 조사 환경에서 DNS 조회에 실패해 ISMS-P 안내서(2023.11) 원문 대신 IT위키 전재본으로 확인했다. 2026-10-31 고시 개정 뒤 안내서가 바뀌었는지는 확인하지 못했다(안내서 재검토 기한은 2026-12-31, [`host-audit-isms-control-mapping.md`](host-audit-isms-control-mapping.md) 참고).
- 개인정보위의 개정 '안전성 확보조치 안내서'(2026-11-05 발간 보도)의 접속기록 부분 원문은 얻지 못했다.
- ISO/IEC 27001·27002는 유료 표준이라 2차 자료로만 확인했다. CIS v8.1 문구는 v8 평가 명세로만 확인했다.

## 1. 법령: 안전성 확보조치 기준 제8조가 바뀌었다

- 현행은 개인정보보호위원회고시 제2026-9호(2026-07-01)이고, 제8조는 제2025-9호(2025-10-31)가 바꿨다. 부칙상 **제8조 제1항·제2항은 2026-10-31부터 시행**된다.
- ① 보관: 개인정보처리시스템에 **접속한 자**(정보주체 제외)의 접속기록을 1년 이상, 5만 명 이상·고유식별·민감정보 처리 시 2년 이상.
- ② 점검: 개인정보취급자의 접속기록과 다운로드 상황을 확인·점검하는 **주기·방법·사후조치절차를 내부 관리계획으로 정하고 이행**한다. 개정 전의 "월 1회 이상 점검"과 다운로드 사유 확인 의무 문구는 없어졌다(개정 전 문구는 2차 자료로 확인).
- ③ 위·변조·도난·분실 방지.
- 다운로드 건수 기준(3배, 1시간 내 50%, 1,000건)은 고시에 없고 회사 지침·양식과 ISMS-P 결함사례 예시에서 온 값이다.
- 제5조③: 권한 부여·변경·말소 내역 3년 보관.

**설계에 미친 영향**: 월 1회 점검의 근거가 법령 문구에서 회사 지침(개인정보처리시스템 월 1회, 그 외 반기)으로 옮겨졌다. 지침에 정한 주기를 지키지 않으면 그 자체가 제8조② 위반이므로 월간 검토는 계속 필요하다.

## 2. ISMS-P 인증기준 (안내서 2023.11)

| 항목 | 요지 | 자주 나오는 결함 |
|---|---|---|
| 2.9.4 로그 및 접속기록 관리 | 로그 유형·보존기간·보존방법을 정하고 위·변조 없이 보존. 개인정보처리시스템 접속기록은 식별자·접속일시·접속지·처리한 정보주체·수행업무를 남긴다 | 보존기간·검토주기 기준 없음, 로그 크기 부족으로 기간 미달, 접속기록에 정보주체·수행업무 누락 |
| 2.9.5 로그 및 접속기록 점검 | 검토 기준(비인가 접속, 과다 조회 등)을 세워 주기적으로 점검하고 결과를 책임자에게 보고, 이상징후에 사후조치 | 이상접속·이상행위 기준 없음, 기준은 있으나 검토 기록 없음, 반기·분기 점검(옛 월 1회 기준 대비), 다운로드 사유 미확인 |
| 2.5.6 접근권한 검토 | 계정·권한 이력 기록, 정기 적정성 검토(분기 1회 이상 권고) | 6개월 이상 미접속 계정 방치 |
| 2.9.6 시간 동기화 | 표준시각 동기화와 **주기적 점검** | 일부 시스템 미동기 방치 |
| 2.10.1 보안시스템 운영 | 정책 타당성 정기 검토(과다 허용, 장기 미사용, 중복·만료, 퇴직자 정책) | 방화벽 정책 미검토, 정책관리대장과 실제 불일치 |
| 2.11.3 이상행위 분석 및 모니터링 | 탐지 기준·임계치 정의와 주기적 조정 | 임계치 초과 미대응 |

공식 보고서 양식은 없다. 심사원은 검토 절차, 검토 결과 보고서, 접속기록 점검 내역, 다운로드 사유 확인 결과, 이상징후 대응 증적이 실제로 있는지 본다.

## 3. 업계 표준의 검토 주기

| 기준 | 주기 | 비고 |
|---|---|---|
| 안전성 확보조치 기준 제8조(현행) | 내부 관리계획으로 정함 | 2026-10-31 전에는 월 1회 이상 |
| ISMS-P 2.9.5 | 법령 주기 | 결함사례상 반기·분기는 부족 |
| ISMS-P 2.5.6 | 분기 1회 이상 권고 | 계정 검토 |
| ISO/IEC 27001:2022 A.8.15·A.8.16 | 정하지 않음 | 로그 생성·보호·분석, 이상행위 모니터링 |
| NIST SP 800-92 (2006) | 중요도에 따름(예: 일·주) | §5.2.3. r1은 2023-10 초안 |
| PCI DSS v4.0 10.4 | 보안 이벤트·핵심 시스템 매일, 나머지는 위험 분석 | 보관 12개월, 최근 3개월 즉시 조회(10.5.1) |
| CIS Controls v8 8.11 | 주 1회 이상(IG2·IG3) | 보관 90일 이상(8.10) |

월간은 국내 심사 기준에서 안전한 하한이고, 즉시 대응이 필요한 이상은 OpenObserve 알림(실시간)이 맡는다.

## 4. 회사 기준과 표준의 차이

회사 지침과 위 표준의 차이(지침 개정 후보)는 회사 내부 문서를 가리키므로 비공개 노트에 둔다. Log Review Report 3부가 메우는 것(시각 동기 점검)과 결재선(정보보호책임자(CISO) 결재 근거)은 ADR-0015에 남아 있다.

## 5. 회사 검토결과 대장의 항목과 수집 데이터 대조 (2026-11-18 기준)

| 항목 | 판정 방식 | 데이터 |
|---|---|---|
| 1 권한 없는 계정 접속, 2 연속 로그인 실패, 3 업무시간 외 접속, 4 업무시간 외 권한 변경, 6 다른 시스템으로 재로그인, 7 비인가 IP 접속, 12 짧은 시간 다중 IP 접속 | 자동 초안 | `security_logs`의 `event_action`·`event_outcome`(sshd·sudo·su), audit 계정 변경 키, 장비 관리자 로그인(VRL이 구조화하는 경우) |
| 13 짧은 시간 명령 집중 | 일부 자동 | sudo 명령만(일반 셸 명령은 수집하지 않음) |
| 5 휴직·휴가자 접속 | 사람 대조 | 계정별 접속일 목록만 자동 |
| 8~11, 14~17 개인정보 조회·다운로드 | 점검 불가 | 애플리케이션 접속기록 미수집 |
| 18 승인 없는 업무, 19 부적합 첨부 | 점검 불가 | 업무 시스템 기록 미수집 |
| 보안정책 1~9 | 1차는 사람이 기입 | FortiGate 정책·Hit-Count 조회 경로 없음 |
