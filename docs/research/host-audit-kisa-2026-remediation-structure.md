# KISA 2026 Unix 서버 가이드의 항목별 구조: 조치 방법·조치 시 영향 서술

- 방법: 두 PDF를 `pypdf`로 쪽별 텍스트로 추출하고, 항목 머리글(`U-NN (상|중|하) UNIX > ...`)로 항목을 나눈 뒤 소제목(점검 내용·점검 목적·보안 위협·참고·대상·판단 기준·조치 방법·조치 시 영향·점검 및 조치 사례) 존재를 항목마다 판정했습니다. 판정은 기계 추출이며, 대표 항목은 원문 텍스트를 직접 읽어 확인했습니다. 2.2절 표의 셀 값도 같은 방식으로 뽑았고, 이미지로만 들어 있는 내용은 보이지 않습니다.
- 원문 인용은 구조 설명에 필요한 짧은 구절만 씁니다. 태그는 **기준 명시**(가이드 본문), **해설·예시**, **관행·권고**(이 조사의 판단)를 씁니다.

## 핵심 답변

1. **2026판은 67개 항목 모두 같은 고정 구조입니다.** 머리글 "U-NN (상/중/하)"와 분류, 항목명 아래에 `개요`(점검 내용, 점검 목적, 보안 위협, 참고), `점검 대상 및 판단 기준`(대상, 판단 기준=양호/취약), `조치 방법`, `조치 시 영향`, `점검 및 조치 사례`가 이 순서로 나옵니다. 9개 소제목이 67/67에 모두 있고 순서가 바뀐 항목도 없습니다(2절 표, 기준 명시).
2. **"조치 시 영향"은 있지만 영향의 크기·위험·시급성을 나타내는 서술은 없습니다.** 67/67에 칸은 있으나 내용은 52개가 "영향 없음"류 문장입니다(정확히 같은 문장 50개, 조건부 2개). 나머지 15개만 항목별 서술입니다. 영향을 등급으로 매기거나 조치 순서·기한을 정한 곳은 Unix 구간에 없습니다(6절).
3. **위험·시급성에 가장 가까운 것은 두 가지뿐입니다.** 항목 머리글의 **중요도 상/중/하**(상 40, 중 18, 하 9)와 `보안 위협` 칸의 "~할 위험이 존재함" 서술입니다. 중요도의 산정 기준은 Unix 구간 어디에도 정의되어 있지 않습니다. 영향·위험·시급성의 등급 체계는 우리가 정해야 합니다(관행·권고).
4. **2021판과 구조가 달라졌습니다.** 가장 큰 변화는 `조치 시 영향`이 항목 맨 끝에서 `개요` 바로 아래(조치 방법 옆)로 올라온 것과, 2021판의 "OS별 점검 파일 위치 및 점검 방법" 블록이 2026판 Unix 구간에서 사라진 것입니다(5절). 2021판의 기본/선택 구분도 2026판에는 없습니다.
5. **일관성 예외는 형식 수준에 머뭅니다.** 소제목 누락은 없고, `참고`가 "-"(내용 없음)인 항목 9개, OS 사례 블록의 구성 방식 차이(OS별 분리 35개, 4개 OS 통합 1블록 32개), 조치 방법이 명령이 아니라 정책 수립인 항목이 있습니다(4절).

- 조치 방법과 조치 시 영향의 위치가 `점검 대상 및 판단 기준` 표의 아래 행이라는 점이 2021판과 다릅니다(5절).
- OS별 명령은 `점검 및 조치 사례`에만 있고, 파일 수정과 값 설정 중심입니다. 점검(진단) 명령과 조치 명령이 따로 나뉘어 있지 않습니다(예외는 4절 8번, 비교는 5절).
- 중요도 상/중/하는 머리글과 각 분류의 "점검항목 항목 중요도 항목코드" 표(p.8~11)에만 나옵니다. 40/18/9로 합쳐 67개입니다.

## 2. 항목별 소제목 존재 여부 (U-01~U-67)

### 2.1 9개 소제목 존재 (67/67)

확인한 소제목은 점검 내용, 점검 목적, 보안 위협, 참고, 대상, 판단 기준, 조치 방법, 조치 시 영향, 점검 및 조치 사례 아홉 개입니다. **67개 항목 모두 아홉 개가 있고, 소제목 순서도 같습니다.** `참고`는 칸이 있으나 값이 "-"인 항목이 9개입니다(아래 표의 참고 열). 판단 기준은 67/67에 양호와 취약 두 줄이 모두 있습니다("해당없음"·"예외" 같은 제3의 판정 값은 없음).

- 분류별 개수(본문 머리글 기준): 계정 관리 13(U-01~13), 파일 및 디렉토리 관리 20(U-14~33), 서비스 관리 30(U-34~63), 패치 관리 1(U-64), 로그 관리 3(U-65~67).
- 본문 머리글은 U-14~U-33을 "파일 및 디렉토리 관리"로 적습니다. 반면 목차 표(p.9)는 U-19~U-33을 "3. 서비스 관리" 표 머리 아래에 둡니다. 소제목 자체의 문제는 아니나 분류 표기가 어긋나는 곳이라 분류는 본문 머리글을 따랐습니다.

## 3. 대표 항목의 원문 구조

### 3.1 U-01 root 계정 원격 접속 제한 (상, p.12~14): 가장 전형적인 형태

- 개요: 점검 내용 한 줄, 점검 목적 한 문장, 보안 위협은 "…시스템 장악 및 각종 공격으로(무차별 대입 공격, 사전 대입 공격 등) 인한 root 계정 사용 불가 위험이 존재함" 식으로 끝납니다. 참고에 용어 해설(※ root 계정, 무차별 대입, 사전 대입, tty, pts)이 붙습니다.
- 판단 기준: "양호 : 원격터미널 서비스를 사용하지 않거나, 사용 시 root 직접 접속을 차단한 경우"와 취약 쪽 한 줄입니다.
- 조치 방법: 한 문장("…접속할 수 없도록 파일 내용 설정").
- 조치 시 영향: "일반적인 경우 영향 없음".
- 점검 및 조치 사례: SOLARIS, LINUX, AIX, HP-UX 각각 `[Telnet]`, `[SSH]`로 나누어 `Step 1)`에 파일과 값만 적습니다(예: `PermitRootLogin No`, p.13~14). 점검 명령(`cat` 등)은 없습니다. 이 항목의 OS별 명령은 파일 수정 지시이고, 서비스 재시작 같은 후속 조치는 적혀 있지 않습니다.
- 가이드 본문의 OS 주의: "CentOS 8, Ubuntu 20.04 이상부터 /etc/securetty 파일이 존재하지 않으며…"(p.13). 배포판 정보는 ※ 주석으로만 나옵니다.

### 3.2 U-02 비밀번호 관리정책 설정 (상, p.15~20): 개별 서술형 영향과 배포판 구분

- 조치 방법에 구체 수치가 있습니다("영문, 숫자, 특수문자를 포함하여 최소 8자리 이상 및 최소 사용 기간 1일, 최대 사용 기간 90일, 최근 비밀번호 기억 4회 이상", p.15). 반면 판단 기준은 "비밀번호 관리 정책이 설정된 경우"로 수치가 없습니다. 판정 수치는 판단 기준이 아니라 조치 방법에 있습니다.
- 조치 시 영향은 개별 서술입니다: "…Web, WAS, DB 연동 구간에서 문제가 발생할 수 있으므로 연동 구간에 미칠 수 있는 영향을 고려하여 적용 필요"(p.15). 영향의 크기는 적지 않고 "고려 필요"만 적습니다.
- 점검 및 조치 사례: SOLARIS, LINUX(`[Redhat]`, `[Debian]`), AIX, HP-UX. Linux는 `pwquality.conf`, `pwhistory.conf`, `pam.d/system-auth`·`common-password` 등 파일별 Step입니다(p.17~18). 설정 값 해설 표(권고값·기능·설명)가 따로 붙습니다(p.16, p.18).

### 3.3 U-05 root 이외의 UID가 '0' 금지 (상, p.27~28): 4개 OS 통합 1블록과 조건부 영향

- 조치 시 영향: "해당 계정에 관리자 권한이 필요하지 않으면 일반적으로 영향 없음"(p.27). 조건을 달았지만 "영향 없음"으로 끝납니다.
- 사례는 `l SOLARIS, LINUX, AIX, HP-UX` 한 블록에 `usermod -u <변경할 UID> <사용자 이름>` 한 줄을 둡니다(p.27). "사용 중인 계정인 경우 명령어를 통한 조치가 적용되지 않을 수 있으므로 /etc/passwd 파일을 통해 변경"이라는 단서가 조치 방법 칸에 있습니다.

### 3.4 U-64 주기적 보안 패치 및 벤더 권고사항 적용 (상, p.160~163): 조치 방법이 명령이 아니라 정책

- 판단 기준 양호는 "패치 적용 정책을 수립하여 주기적으로 패치 관리를 하고 있으며, 패치 관련 내용을 확인하고 적용하였을 경우"입니다(p.160). 증적이 설정값이 아니라 정책 존재입니다.
- 조치 방법은 "OS 관리자, 서비스 개발자가 패치 적용에 따른 서비스 영향 정도를 파악하여…"라고 합니다. **영향 파악을 조치자에게 맡기는 문장**입니다. 정작 `조치 시 영향` 칸은 "일반적인 경우 영향 없음"입니다. 같은 항목 안에서 두 칸이 서로 다른 말을 합니다.
- 사례는 SOLARIS에 `pkg list`, `pkg update` 명령과 `[Oracle support이 존재하는 경우/않는 경우]` 분기가 있습니다(p.160~161).

### 3.5 U-66 정책에 따른 시스템 로깅 설정 (중, p.166~170): 영향이 수치 없는 구체 서술인 드문 경우

- 조치 시 영향: "아래 제시한 모든 로그를 설정할 경우, 시스템 성능과 로그 저장에 따른 서버 용량 부족 문제가 발생할 수 있으므로 시스템 운영 환경과 특성을 고려하여 적용"(p.166). 성능·용량이라는 영향의 종류를 이름 붙이는 몇 안 되는 항목입니다. 크기(예상 용량 등)는 없습니다.
- 사례는 `[syslog]`, `[rsyslog]` 등 서비스별 분기와 로그 종류·경로 표(`*.info /var/log/syslog.log` 형식)를 줍니다.

| 개요 그룹명 | `취약점 개요`, `점검대상 및 판단기준` | `개요`, `점검 대상 및 판단 기준` (용어도 패스워드 → 비밀번호) |
| **조치 시 영향의 위치** | **항목 맨 끝**, `점검 및 조치사례` 다음(72/72). U-01은 인쇄 p.8(PDF 16), U-72는 인쇄 p.145(PDF 153) | **`조치 방법` 바로 아래 행**, 사례보다 앞(67/67) |
| 점검 방법 블록 | `OS별 점검 파일 위치 및 점검 방법`(예: `#cat /etc/ssh/sshd_config` 출력 예시 포함)이 72개 중 62개에 있고, 10개(U-22, 25, 42, 43, 60, 61, 64, 65, 68, 72)에 없음 | 해당 소제목이 Unix 구간에 없음(텍스트에서 0건) |
| 조치 사례 형태 | `■ OS`별 `Step 1) vi 편집기를 이용하여 … 파일 열기`, `(수정 전)`/`(수정 후)` 대비 | `l OS`별 `Step 1) … 파일 내에 … 값 수정`, 수정 전후 대비 표기 없음(U-01 비교) |
| 참고 칸이 비는 경우 | "-"로 표기(예: 2021 U-42, PDF 93쪽) | 같은 방식, 9개 |
| 조치 시 영향 문구 | "일반적인 경우 영향 없음"으로 시작하는 항목 46/72 | 같은 문장 50/67 + 조건부 2 |
| 중요도 정의 | Unix 구간에 중요도 상/중/하의 정의 없음(머리글·표에만 등장) | 같음 |

- **조치 시 영향 문구는 대부분 2021판에서 가져왔습니다.** U-02(2021 인쇄 p.12 / 2026 p.15)와 U-72→U-66(2021 인쇄 p.145 / 2026 p.166)의 영향 문장은 "패스워드"→"비밀번호", "시스템 퍼포먼스"→"시스템 성능" 정도만 다릅니다. 영향 서술의 깊이는 2021판과 같은 수준입니다.
- 항목 번호가 가리키는 항목이 판마다 다릅니다(예: 2021 U-13 SUID, 2026 U-13 비밀번호 암호화 알고리즘, baseline 문서 2절). 이 조사의 범위는 구조이므로 항목 대응표는 만들지 않았습니다.
- 범위 밖: 2021판 소제목 존재 판정도 텍스트 추출 기반입니다. 항목별 내용 변경(판단 기준 문구, 명령어 갱신)은 확인하지 않았습니다.

## 6. 영향·위험·시급성: 가이드에 없는 것

**가이드는 영향·위험·시급성을 평가하는 체계를 제공하지 않습니다.** 확인한 범위(Unix 서버 U-01~U-67, p.7~171)에서 다음과 같습니다(기준 명시, 부재 확인).

| 요소 | 가이드에 있는가 | 내용 |
|---|---|---|
| 조치 시 영향(서술) | 있음, 67/67 | 52개는 "영향 없음"류. 15개는 "…문제가 발생할 수 있으므로 고려 필요" 식의 서술. 등급·수치·소요 시간·재시작 필요 여부의 정형 필드는 없음 |
| 보안 위협(서술) | 있음, 67/67 | 미조치 시 피해 서술("~위험이 존재함"). 발생 가능성·피해 크기의 등급은 없음 |
| 중요도 상/중/하 | 있음, 67/67 | 머리글과 분류별 표(p.8~11). **산정 기준 정의는 없음**. 위험·영향·시급성 중 무엇을 반영하는지도 적혀 있지 않음 |
| 위험도·심각도 등급 | 없음 | Unix 구간에 "위험도" 항목 또는 소제목이 없음 |
| 시급성·조치 기한·조치 우선순위 | 없음 | "시급", "긴급", "우선순위" 같은 문구는 Unix 구간 어디에도 항목 평가로 쓰이지 않음 |
| 조치의 재현 가능 여부(서비스 재시작, 롤백 방법) | 없음 | 항목 구조에 롤백·재시작 필드가 없음. U-01 사례도 설정 변경만 적음 |

- 중요도 상/중/하는 이 조사의 대상 질문(영향·위험·시급성)에 가장 가까운 필드이므로 우리 체계의 입력값으로 쓸 수는 있습니다. 다만 **의미가 정의되어 있지 않으므로 "시급성"으로 읽는 것은 해석**입니다(관행·권고).
- 따라서 Host Audit에서 영향·위험·시급성을 보고서에 쓰려면, `조치 시 영향` 문장은 근거 인용으로만 쓰고 등급과 우선순위는 우리가 정해야 합니다(관행·권고). 정의는 이 조사의 범위가 아니라 상위 map #477의 결정 사항입니다.
