# 15. 월간 Log Review Report: Host Audit 실행이 초안을 만들고 사람이 판정해 3단 결재한다

ISMS-P 2.9.5(로그 및 접속기록 점검)의 증적은 수동 런북(`docs/runbooks/monthly-log-review.md`)으로만 남기고 있었다. 런북은 사람이 OpenObserve에서 쿼리를 하나씩 돌려 비공개 노트에 옮겨 적는 방식이라 매달 같은 형식으로 남는다는 보장이 없고, 회사 로그·보안정책 검토결과 대장(AK-034)의 검토 항목과도 맞춰져 있지 않았다. 그래서 **Log Review Report**를 월간 Host Audit 메일의 별도 첨부로 낸다. 근거 조사는 [`docs/research/log-review-isms-criteria-2026-11.md`](../research/log-review-isms-criteria-2026-11.md)다.

1. **Host Audit 정기 실행 안에서 만든다.** 같은 메일에 붙고 보관(RustFS `host-audit` 버킷, 3년 잠금)·SHA-256·재발송 흐름을 그대로 쓴다. 수시 실행은 플래그로 켤 때만 만든다(같은 달 결재본이 여러 부 생기지 않게). Host Audit 보고서의 일부가 아니라 별도 A4 HTML 첨부다.
2. **기간은 전월 달력 한 달(KST)이고 데이터는 OpenObserve에서만 읽는다.** 서버 로컬 로그는 한 달치가 남지 않는다. OpenObserve 보존은 1년이다. 호스트에는 아무것도 하지 않으므로 ADR-0009의 읽기 전용 원칙은 그대로다.
3. **검토 항목은 AK-034가 기준이다.** 1부는 로그 검토 19개 항목, 2부는 보안시스템 정책 적정성 9개 항목(Security Policy Review), 3부는 로그 관리 상태(수집 공백·보존·시각 동기·백업·알림 이력)다. 수집하지 않는 데이터가 필요한 항목(애플리케이션의 개인정보 조회·다운로드 기록, 인사 정보, 업무 승인 내역)은 빼거나 "해당 없음"으로 쓰지 않고 **"점검 불가"와 그 사유**로 매달 보고한다. 범위는 OpenObserve에 수집되는 서버·네트워크·보안 장비·서비스 로그다.
4. **자동은 초안까지, 판정은 사람이다.** 보고서는 집계·임곗값 초과 건·자동 판정("이상 없음"/"확인 필요")과 판정 기준(임곗값)을 채우고, 최종 판정·점검자 소견·조치 내역 칸은 비워 둔다. 결재란은 점검자 → 정보보호관리자 → 정보보호책임자(CISO) 3단이다. 서명본 스캔은 같은 실행 경로의 `signed/`에 올리고, 다음 달 보고서가 전월 서명본이 올라왔는지 적는다.
5. **조회는 OpenObserve 조회 전용 계정으로 한다.** `host_audit` AppRole에 읽기 권한만 더한다. admin 자격증명은 쓰지 않는다. 판정 기준 목록(정상 출발지, 내부 주소 대응, 개인정보처리시스템 표시)은 OpenBao `inventory/config/`에서 읽고 Git에는 두지 않는다.
6. **조회 실패는 메일을 막지 않는다.** 실패한 항목은 "조회 실패"로 적고 Host Audit 보고서는 그대로 보낸다. "확인 필요" 항목으로 알림(webhook)을 보내지 않는다. 즉시 대응은 OpenObserve 알림이 맡는다.

## Considered Options

- **수동 런북 유지**: 비용이 가장 적지만 형식이 매달 달라지고, 2.9.5 결함사례("기준은 있으나 검토한 기록이 없음")를 막을 장치가 사람의 기억뿐이다.
- **자동 판정 확정(사람은 서명만)**: 심사에서 "자동 집계만 있고 사람이 검토한 흔적이 없음"으로 지적되는 형태다. CISO가 검토하지 않고 서명하는 구조를 만든다.
- **별도 플레이북·별도 메일**: 실행·보관·해시·재발송을 한 벌 더 만들고 두 실행의 대응을 맞춰야 한다. 사용자가 같은 메일 첨부를 원했다.
- **OpenObserve 대시보드·예약 보고서**: 결재본으로 고정된 파일과 해시가 남지 않고, "점검 불가" 항목을 표현하기 어렵다.
- **로그 검토와 보안정책 검토를 한 용어로 묶기**: 정책 검토는 로그가 아니라 방화벽 정책 자체를 읽는다. 같은 보고서·같은 서명으로 나가지만 개념은 나눈다(`CONTEXT.md`의 Security Policy Review).

## Consequences

- 1부 19개 항목 중 상당수(개인정보 조회·다운로드 관련)는 애플리케이션 접속기록을 수집할 때까지 매달 "점검 불가"로 나온다. 개인정보처리시스템에는 안전성 확보조치 기준 제8조의 접속기록 점검이 서버 로그만으로 채워지지 않는다는 공백이 보고서마다 드러난다. 수집은 후속 과제다.
- 2부는 1차 구현에서 사람이 채우는 빈 표다. FortiGate 정책·Hit-Count 자동 조회는 후속 과제다.
- `host_audit` AppRole이 처음으로 OpenObserve 읽기 권한을 갖는다. 메일·잠금 버킷에 출발지 IP·계정명이 들어가므로 메일 수신자를 점검자·결재자로 한정해야 한다.
- 수동 런북은 조회 절차가 아니라 "보고서를 받아 확인·소견 기입·결재받는 절차"로 바뀐다.
- 결재 단계가 회사 양식(AK-034, 정보보호관리자 서명만)보다 많다. 회사 지침(RS-092)에 CISO 보고 근거를 넣는 개정은 후속 과제다.
- CentOS 6 호스트는 시각 동기 상태를 수집하지 않아 3부에서 "확인 불가"로 나온다.
- ADR-0009의 "Host Audit은 로그를 보지 않는다"는 전제를 이 ADR이 보완한다. 호스트 쪽 읽기 전용 범위는 바뀌지 않는다.
