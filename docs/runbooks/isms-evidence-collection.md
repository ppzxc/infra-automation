# ISMS 로그·백업 운영 증적 수집 런북

로그 수집·보관과 백업·복구 체계의 운영 증적을 만들고 소명서로 묶는 절차다. 대응 기준은 ISMS 2.9.3(백업 및 복구관리), 2.9.4(로그 및 접속기록 관리), 2.9.5(로그 및 접속기록 점검)이다. 근거 조사는 [ISMS 인증기준 조사](../research/host-agents-isms-log-backup-criteria.md), 정기 점검은 [월간 로그 점검 런북](monthly-log-review.md), 복구 시험은 [백업 복원 시험 런북](backup-restore-drill.md)을 따른다.

공개 저장소이므로 호스트 주소·포트·접근키와 실제 수집 결과는 이 문서에 쓰지 않는다. 수집 결과(CSV, 화면 캡처, 소명서)는 모두 비공개 경로에 둔다. 이 문서에는 절차·쿼리·양식만 있다.

## 원칙

- **시작일은 실측으로 쓴다.** 호스트별 첫 수집일·첫 스냅샷일을 데이터에서 뽑아 "N월 N일부터"로 적는다. 체계 구축 이전 기간은 증적을 소급해 만들지 않고, 소명서로 설명한다.
- **읽기만 한다.** OpenObserve 조회와 백업 저장소 목록 조회만 한다. 호스트 변경은 이 절차에 없다(복구 시험만 임시 경로에 쓴다).
- **원본과 정리본을 구분한다.** 도구 화면을 그대로 찍은 캡처가 원본이다. CSV로 다시 그린 표는 "CSV 기반 정리"로 표기하고 원본과 함께 제출한다.
- **시각은 KST로 고정한다.** 일별 집계에서 일 경계가 UTC로 잡히면 건수가 달라진다(§2).

## 2. 로그 쿼리

OpenObserve 로그 화면에서 SQL 모드로 실행한다. 시간 범위는 체계 가동 이전부터 오늘까지로 넉넉히 잡는다. 아래 `+32400000000`은 KST(UTC+9)를 마이크로초로 더한 값이다.

호스트별 첫·마지막 수집일과 건수(E2):

```sql
SELECT host_name,
  to_char(to_timestamp_micros(min(_timestamp)+32400000000), '%Y-%m-%d %H:%M') AS first_seen_kst,
  to_char(to_timestamp_micros(max(_timestamp)+32400000000), '%Y-%m-%d %H:%M') AS last_seen_kst,
  count(*) AS records
FROM "system_logs" GROUP BY host_name ORDER BY host_name
```

일별 호스트 수와 건수(E3). 호스트×일 매트릭스는 호스트·일 단위로 집계한 결과를 CSV로 내려 표로 만든다.

```sql
SELECT to_char(to_timestamp_micros(_timestamp+32400000000), '%Y-%m-%d') AS day_kst,
  count(distinct host_name) AS hosts, count(*) AS records
FROM "system_logs" GROUP BY day_kst ORDER BY day_kst
```

`histogram(_timestamp, '1 day')`는 일 경계가 UTC라서 KST 집계와 값이 다르다. 증적에는 위 `to_char` 방식을 쓴다.

`backup_logs`의 호스트 열은 `host`이고 `host_name`이 아니다. 실패 이력(E8):

```sql
SELECT to_char(to_timestamp_micros(_timestamp+32400000000), '%Y-%m-%d %H:%M:%S') AS time_kst,
  host, job, command, error
FROM "backup_logs" WHERE success = false ORDER BY _timestamp
```

수집 대상이 아닌 호스트(에이전트 제외, 별도 수집)는 표에서 빼지 말고 "대상 외"와 사유를 적는다.

## 3. 백업 현황 수집

- **실행 이력**: `backup_logs`에서 `job = 'backup'`의 호스트별 성공·실패 건수와 첫·마지막 일시를 뽑는다.
- **스냅샷 현황**: 백업 저장소의 호스트별 버킷에서 `snapshots/` 객체 수와 수정 시각을 읽기 전용으로 센다. 호스트 버킷과 서비스용 버킷(Host Audit, OpenObserve 데이터)을 구분해 호스트 표에는 호스트 버킷만 넣는다.
- **스냅샷 수 해석**: 스냅샷 수는 보존 정책(`forget`) 적용 후 **현재 보관 중인 개수**다. 누적 실행 횟수는 `backup_logs`의 성공 건수를 쓴다. 두 값이 다른 것은 정상이다.
- **복구 시험(E9)**: [백업 복원 시험 런북](backup-restore-drill.md) §3대로 한 호스트의 `/etc`만 임시 경로에 복원해 원본과 대조하고 삭제한다. 대상 호스트는 승인을 받고, 무작위가 아니라 운영자가 지정했다면 그 사실을 결과에 적는다. 서버 전체 복구(재해 복구) 시험이 아님을 결과에 명시한다.

## 4. 화면 캡처

- 모든 화면에 **시간 범위, 호스트명, 조회 쿼리**가 보이게 찍고, 파일명에 증적 번호와 날짜를 넣는다(`E2_system_logs_host_summary_YYYYMMDD.png`).
- 가능하면 CSV 원본도 함께 보관한다. 캡처가 의심받을 때 대조 자료가 된다.
- 브라우저 자동화(Playwright)로 찍을 때의 주의:
  - 시스템에 Chromium 실행 라이브러리가 없으면 패키지 파일을 사용자 경로에 풀어 `LD_LIBRARY_PATH`로 지정한다. 호스트에 설치하지 않는다.
  - 한글 글꼴이 없으면 화면 글자가 깨진다. OpenObserve 화면은 영어 로캘로 캡처하고, 직접 만든 표는 글꼴 파일을 사용자 경로에 두어 적용한다.
  - 스트림 상세 화면의 버튼은 삭제 버튼과 같은 줄에 있으므로 `data-test` 속성으로만 선택하고 설정 저장은 누르지 않는다.
  - 알림 이력 화면의 이름 필터 드롭다운은 자동화가 불안정하다. 이름별 집계는 알림 평가 이력(`triggers` 스트림)을 조회해 표로 만들어 대체한다.

## 5. 소명서

체계 구축 이전 공백과 예외를 한 문서로 설명한다. 구성:

1. 목적과 범위(대응 기준, 기준일, 대상 호스트 수)
2. 증빙 기간과 이전 공백(호스트별 시작일 분포, 소급하지 않았다는 설명, 이후 정례화 계획)
3. 로그 수집·보관 체계(유형, 수집 호스트 수, 보존)
4. 백업 체계와 현황(대상 수, 성공·실패 건수, 보관 스냅샷 해석)
5. 이상 징후 감시(알림 규칙 수, 수집 중단·백업 실패 알림 이력)
6. 예외와 조치(실패 건별 일시·호스트·원인·결과)
7. 복구 시험 결과와 범위 한계
8. 개선 필요 사항(소산 백업 등)
9. 부록(호스트별 현황 표, 증적 이미지)

작성 규칙:

- 원인을 확인하지 못한 예외는 추측하지 않고 확인된 사실(일시, 이후 정상 여부)만 적는다. 심사원이 물을 수 있으므로 미확인 항목 목록은 작성자가 따로 가진다.
- 수치는 CSV에서 계산해 채우고 손으로 옮겨 적지 않는다. md와 인쇄용 html은 같은 데이터에서 함께 생성한다.
- 작성자·승인란은 사람이 채운다.
- 관리번호가 정정된 호스트는 정정 경위와 편입일을 적는다. 이전 이름의 증적이 없다면 없다고 적는다.

## 6. 주기와 보관

- 분기마다 E2~E4, E7, E8을 다시 뽑고 복구 시험(E9)을 한 번 수행한다. 월간 로그 점검 기록(E5)은 매달 누적한다.
- 소명서의 기준일 값은 심사 직전에 다시 생성한다.
- 결과물은 비공개 경로에 두고, 이슈에는 수행 여부와 통과 여부만 적는다.
