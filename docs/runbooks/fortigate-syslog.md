# 포티게이트 방화벽 로그 수신 런북

> 포티게이트 방화벽(IDC HA 쌍과 사무실 장비)의 ISMS 증적 로그가 OpenObserve `security_logs`까지 가는 경로, 장비 쪽 거름 기준, 점검 절차다(Spec #282 / #283). 수신 경로는 [스위치 syslog 런북](switch-syslog.md)을 재사용한다. 공개 저장소라 IP·포트·장비 명령과 값은 적지 않으며, 장비에서 사람이 하는 설정의 체크리스트는 담당자의 로컬 비공개 자료에 있다.

## 1. 경로

```text
방화벽 ──syslog(UDP)──▶ syslog-ng 컨테이너 ──▶ 장비별·일별 파일 ──▶ 호스트 otelcol(filelog) ──▶ OpenObserve security_logs
```

| 구간 | 내용 |
|---|---|
| 수신 | 스위치와 같은 syslog-ng 컨테이너가 받는다. 수신 허용 목록에 방화벽 출발지를 등록해야 한다(2절 HA 멤버 구성). |
| 파일 보관 | `/var/log/remote/fortigate/<송신 장비>/<날짜>.log`. **스위치 파일(`/var/log/remote/<송신 장비>/`)보다 한 단계 깊은 경로**에 써서 스위치용 수집 경로(`/var/log/remote/*/*.log`)가 방화벽 줄을 한 번 더 읽어 `system_logs`에 중복 수집하지 않게 한다. 호스트 logrotate 보관 기간은 스위치와 같다. |
| 중앙 수집 | 호스트 KV `otel_extra_logs`에 `path=/var/log/remote/fortigate/*/*.log`, `stream=security_logs`, `service=fortigate-syslog`를 더한다. 절차와 KV 주의는 스위치 런북 2절과 같다(PATCH 불가, 전체를 읽어 합쳐 `cas`, 값 출력 금지). 코드 변경은 필요 없다. |
| 분류·보관 | `security_logs`. 스위치(`system_logs`, `switch-syslog`)와 서비스 이름으로 구분한다. 보관은 서버 전역 365일(ISMS 로그 1년). |
| 중앙 변환 | 추가 경로에는 파서가 적용되지 않는다(ADR-0006 §2.3). 원문은 그대로 저장되고 `security_semantics` 함수는 이 레코드를 건드리지 않는다. 대신 같은 보안 로그 파이프라인의 다음 함수 `fortigate_semantics`가 `fortigate-syslog` 레코드에만 장비(`device_name`, 관리번호 `device_id`)·유형·하위 유형·동작·출발지·사용자·정책 식별자 필드를 **추가**한다(필드 표는 [OpenObserve 구성](../openobserve_config.md), ADR-0008, Spec #282 / Ticket-2). 해석할 수 없는 줄은 그대로 통과한다. |

장비 구분은 파일 경로 속성과 원문의 장비 이름으로 한다. 두 HA 멤버가 서로 다른 장비 이름을 가져야 검색에서 구분된다.

## 2. 장비 쪽 로그 거름 기준

거름은 장비 쪽에서 1차로 한다. 핵심은 장비 전역 필터가 아니라 **정책별 로그 설정**이다.

| 구분 | 대상 |
|---|---|
| 수집(포함) | 관리자 접속·로그인 성공/실패, 설정·정책·계정·권한 변경, HA 전환·재부팅·인터페이스 이벤트, VPN 접속, UTM 탐지·차단(IPS·AV·웹필터), 정책 거부 트래픽, 장비 자체 접속 거부 |
| 제외 | 허용(accept) 트래픽 전체, 멀티캐스트, 스니퍼, 음성 로그 |
| 예외 | 허용 정책 중 중요 구간(예: DMZ에서 내부망)만 정책 단위로 로그를 켠다. 대상 정책 목록은 비공개 자료에 둔다 |

- 정책별 로그 설정 원칙: 허용 정책은 기본 로그 끔, 중요 구간만 켬. 맨 아래에 **로그를 켠 명시적 거부 정책**을 둔다(암묵적 거부는 로그가 남지 않는다).
- 새 정책을 만들 때 이 기준으로 로그 설정을 정한다.
- 전송은 현재 **UDP**(기본 형식)와 고정된 출발지 주소를 쓴다. 정확한 명령과 값은 FortiOS 버전마다 다르므로 사용 중인 버전 문서로 확인하고 비공개 자료에만 적는다.
- **TCP(신뢰성 전송) 전환은 수신기를 먼저 바꿔야 한다.** 2026-10-28 장비 설정을 `reliable`(TCP)로 바꿔 시험했더니 수신기의 `tcp()` 소스(줄바꿈으로만 메시지를 나눔)와 맞지 않아 메시지가 이어진 채 최대 크기에서 잘렸다. 파일 줄이 필드 중간에서 시작하고 유입이 분당 약 1,500건에서 수 건으로 떨어졌다. 장비를 UDP로 되돌려 복구했다. 스펙(#282)의 TCP 전제는 아직 충족되지 않았으며, 수신기에 별도 소스(길이 접두 프레이밍을 지원하는 `syslog()` 드라이버)를 추가하는 설계가 선행돼야 한다. 그 전에는 장비에서 `reliable`을 켜지 않는다.
- TCP로 바꾼 뒤 검증은 연결이 맺힌 **뒤 몇 분 이상** 건수와 파일 줄 시작 형식(`<월 일 시각> <출발지> date=`)을 본다. 전환 직후 1분은 UDP로 보낸 잔여 로그라 정상처럼 보인다. 호스트의 `ss`는 도커 DNAT 연결을 보지 못하므로 수신기 컨테이너 안에서 확인한다.

### 대상 장비

- 장비 이름은 관리번호(소문자, 인벤토리 호스트명)를 쓴다: IDC 쌍 `ns0380`·`ns0381`, 사무실 `ns0399`.
- 모델·소프트웨어 버전·적용 순서·현재 장비 설정 상태는 공개하지 않는다. 명령과 항목 이름은 버전마다 다를 수 있으므로 사용 중인 버전의 공식 문서로 확인하고, 확인한 값만 비공개 체크리스트에 적는다.
- 실제 로그 샘플이 있어야 필드 추출을 확정할 수 있다(5절).

### HA 멤버 구성

- HA 쌍의 두 멤버는 hostname을 서로 다르게(`ns0380`, `ns0381`) 한다. 쌍은 같은 출발지로 로그를 보내므로 **멤버 구분은 출발지가 아니라 원문의 hostname(장비 이름)으로 한다.**
- **한계(수용 위험)**: 대기 멤버에 직접 접속한 이력과 대기 멤버의 로컬 이벤트는 중앙에서 직접 수집하지 못할 수 있다. HA 관리 인터페이스 사용 여부, 근거, 대안은 비공개 체크리스트에서 관리하고 확인된 뒤에만 이 절에 반영한다.
- syslog-ng 수신 허용 목록은 **IDC 출발지 1개 + 사무실 1개**다. 값은 비공개 자료에 둔다.

## 3. 점검 절차

1. **장비 설정**: 비공개 체크리스트로 로그 전송(대상, 형식, 출발지 고정), 정책별 로그 설정, HA 관리 인터페이스 구성을 확인한다.
2. **허용 목록**: syslog-ng 수신 허용 목록에 IDC 출발지 1개와 사무실 변환 출발지 1개가 있는지 본다.
3. **수신**: syslog-ng 통계에서 처리 건수가 늘어나는지 본다(방화벽은 로그가 계속 나오므로 멈추면 바로 보인다). 늘지 않으면 장비 전송 설정, 허용 목록, 경로를 순서대로 본다.
4. **파일**: `/var/log/remote/fortigate/` 아래에 장비별 디렉터리와 오늘 날짜 파일이 생기는지 본다. 스위치 경로와 같은 단계에 방화벽 디렉터리가 생겼다면 설정이 틀린 것이다(중복 수집 위험).
5. **OpenObserve**: `security_logs`에서 `service_name='fortigate-syslog'`의 최신 시각을 장비 이름별로 본다. IDC 두 멤버(`ns0380`, `ns0381`, 장애 전환 뒤에는 새 primary 이름)와 사무실(`ns0399`)이 보여야 한다. 평소에는 primary 이름만 보일 수 있다. 없으면 호스트 otelcol 설정에 경로가 있는지와 서비스 상태를 본다.
6. **거름 확인**: 허용 트래픽이 섞여 들어오지 않는지(건수가 비정상적으로 많지 않은지), 관리자 로그인 시도·정책 거부가 들어오는지 확인한다.
7. **대기 멤버 직접 접속**: 중앙에 남지 않을 수 있다(2절 한계). 장애 전환 시험을 한 경우 새 primary 이름으로 로그가 이어지는지만 본다.
8. **다른 경로 영향 없음**: 같은 시각의 `switch-syslog`, 서버 로그가 평소대로 들어오는지 본다.

## 4. 신규 방화벽 편입 절차

1. 장비 이름을 고유하게 정한다(HA는 멤버마다 다른 hostname). 관리번호 규칙은 CONTEXT.md의 Inventory Hostname을 따른다.
2. 비공개 체크리스트에 장비 항목을 더하고 로그 전송과 정책별 로그 설정을 적용한다.
3. syslog-ng 수신 허용 목록에 출발지(HA 쌍은 공통 출발지 1개)를 더하고 `syslog-ng-ctl reload`로 설정만 다시 읽힌다.
4. 3절의 점검 절차로 파일 생성과 `security_logs` 도착을 확인한다.
5. 로그가 `security_logs`에 도착하는 것을 확인한 뒤 수신 중단 감시 목록(`o2c_fortigate_syslog_roster`, HA 쌍은 `ns0380+ns0381`, hostname을 관리번호로 못 바꾼 장비는 원래 이름 그대로도 가능, 관리번호 매핑은 `o2c_fortigate_device_aliases`)에 더한다([알림 런북](alerts.md)). 설정 백업 대상 등 다른 티켓의 목록도 더한다.
6. 비공개 체크리스트에 완료 일자를 적는다.

## 5. 알려진 한계

- 원문 시각의 시간대는 장비 설정에 의존한다. 증적 기준 시각은 수집 시각이다.
- **필드 추출은 실로그 샘플로 검증됨**(검증 범위: 관리자 로그인 성공/실패, 정책·로그 설정 변경(GUI·jsconsole·ha_daemon), 로컬·포워드 트래픽(정책 0 포함), IPsec 터널 통계, UTM(ips·virus·dlp·anomaly), HA 인터페이스 실패, FSSO, 엔드포인트. 검증되지 않은 종류: HA 전환(상태 변경) 실제 줄, SSL VPN 사용자 로그인/로그아웃·로그인 실패 줄, 실제 장비가 만든 웹필터·앱제어 줄, IPv6 주소). 실제 FortiOS 줄을 가짜 값(IP는 `192.0.2.x`, 장비 `Example_Branch_FW`·`ns0001`, 계정 `example-admin`)으로 치환한 `tests/fixtures/fortigate_real_lines.tsv`를 `tests/test_openobserve_vrl.py`가 함수에 통과시킨다. 실측으로 고친 점: VPN 터널 통계 줄의 `user="<상대 장비 주소>"`는 사용자가 아니라서 `user_name`을 만들지 않는다. `ui="ha_daemon"`처럼 주소가 없는 줄은 `source_address`가 비고, HA 줄은 `action` 키가 없어 `event_action`이 비는 것이 정상이다. 검증되지 않은 종류의 줄이 처음 들어오면 필드가 비어 있는지 확인한다.
- 알림(관리자 로그인 실패·정책·계정 변경·HA 전환·중대 탐지·수신 중단)은 [알림 런북](alerts.md)의 방화벽 절이 다룬다(Spec #282 / Ticket-3, 같은 실로그 샘플로 검증, 검증 범위·한계는 같다). 설정 백업·변경 알림은 이 런북의 범위 밖이다([알림 런북](alerts.md#fortigate-config-change)).
- 허용 트래픽은 수집하지 않으므로 "허용된 접속이 있었는지"는 이 로그로 증명되지 않는다. 중요 구간만 정책별로 켠 범위에서만 남는다.
