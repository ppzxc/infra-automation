# 관리용 웹 접점 루프백 바인드와 불필요 관리 인터페이스 제거 (#369)

관리용 웹 인터페이스는 루프백에만 바인드하고, 외부 접근은 기존 허용 출발지 기반 리버스 프록시 한 경로로만 열어 둔다. 쓰지 않는 관리 인터페이스는 제거한다. 스펙 #364 / Ticket-2.

이 저장소에는 대상 서버의 compose 원본이 없다(ADR-0011, 수동 관리 compose). 그래서 변경은 서버에서 운영자 승인 후 직접 하고, 저장소에는 이 런북과 #377이 읽을 기대치만 둔다. 공개 저장소이므로 주소·포트·출발지·호스트 식별자는 적지 않는다. 구체값은 모두 비공개 경로(`~/.local/share/infra-automation/sec-review-20261026/`)에 둔다.

## 금지 사항

- 시크릿 저장소 스택(overseer: OpenBao·Semaphore 등)은 이 티켓에서 재생성하지 않는다. 키가 재시작 입력으로만 주입되므로 재생성하면 Semaphore가 죽는다. overseer 스택 안의 게시 포트는 현황만 기록하고, 변경은 별도 승인·별도 절차로 넘긴다.
- 시크릿 값을 읽거나 출력하지 않는다. `.env`·env 파일·컨테이너 환경변수를 열어 보지 않고, 권한·소유자·경로만 본다. 명령 결과를 기록할 때 값이 섞였으면 폐기한다.
- 방화벽 체인을 직접 만지지 않는다. 접근 제어는 바인드 주소와 리버스 프록시 허용 출발지로만 한다.
- 이슈·PR·커밋에는 통과 여부만 적는다. 스냅샷 원본, 시험 출발지, 제거 목록은 비공개 경로에 둔다.
- 항목별 운영자 승인 없이 적용하지 않는다. 한 번에 한 항목만 적용한다.

## 적용 전 기준선

1. 롤백 절차(아래 "롤백")의 각 항목 되돌림 방법을 비공개 노트에 먼저 적는다. 바꾸기 전의 compose 해당 서비스 정의는 수정 전 사본으로 서버의 비공개 경로에 보관한다(내용에 시크릿이 있으면 사본 권한을 0600으로 한다).
2. 기준선 스냅샷을 수집한다. 읽기 전용이며 같은 명령을 적용 후에도 그대로 쓴다.

```bash
scripts/collect-security-baseline.sh --label <라벨> --ssh <계정>@<호스트>
```

3. 스냅샷의 "열린 접점·컨테이너 게시 포트" 구간에서 외부 대역(모든 주소)에 열려 있는 관리용 웹 접점 목록을 뽑아 비공개 노트에 적는다. 이 목록이 아래 체크리스트의 대상이다.
4. 서버에서 실제 청취 주소를 읽기 전용으로 확인한다.

```bash
ss -lnt
```

5. 허용 출발지에서 리버스 프록시 경로로 현재 정상 로그인되는지 먼저 확인해 둔다(적용 후 비교 기준).

## 승인 항목별 체크리스트

항목마다 운영자 승인을 받고 한 항목씩 적용한다. 항목 ID는 비공개 노트의 목록과 맞춘다. overseer 스택 소속 접점은 이 표에 넣지 않는다.

| 항목 | 내용 | 승인 전 확인 | 적용 | 적용 후 확인 | 롤백 | 운영자 승인 |
|---|---|---|---|---|---|---|
| M-1 | 외부 대역에 열린 관리 웹 접점의 바인드를 루프백으로 변경(접점마다 한 행씩 복제) | 프록시가 이 접점을 루프백으로 도달 가능, 수정 전 사본 보관 | compose의 `ports:`를 루프백 주소 접두로 바꾸고 해당 서비스만 재생성 | 청취 주소가 루프백만, 프록시 경로 로그인 정상 | R-1 | [ ] 승인자·시각은 비공개 노트 |
| M-2 | 리버스 프록시 경로가 허용 출발지 목록(whitelist) 한 경로뿐인지 확인, 다른 경로가 있으면 제거 | 현재 경로 목록 기록 | 불필요 경로 삭제(프록시 설정 수정은 bind mount라 `sed -i`를 쓰지 않는다) | 허용 밖 출발지 거부 | R-2 | [ ] 승인자·시각은 비공개 노트 |
| M-3 | 쓰지 않는 관리 인터페이스 제거(사용 여부는 운영자가 확인) | 제거 목록과 근거를 비공개 노트에 작성, 사용처 없음 확인 | 해당 서비스·게시 포트 제거 | 기준선 diff에 의도한 제거만 있음 | R-3 | [ ] 승인자·시각은 비공개 노트 |

## 롤백

적용 전에 쓴다. 롤백도 overseer 스택은 건드리지 않는다.

| ID | 되돌림 |
|---|---|
| R-1 | 보관한 수정 전 사본의 `ports:` 정의로 되돌리고 해당 서비스만 재생성한다. 청취 주소가 기준선과 같아졌는지 확인한다 |
| R-2 | 보관한 수정 전 프록시 설정으로 복원한다(bind mount는 파일을 덮어쓰기로 복원, `sed -i` 금지) |
| R-3 | 수정 전 사본의 서비스 정의를 되돌리고 해당 서비스만 재생성한다 |

롤백 후에도 같은 수집 명령으로 스냅샷을 떠서 기준선과 diff가 비는지 확인한다. 판단 기준은 허용 출발지 로그인 실패, 모니터링 알림 발생, 승인자의 중단 지시 중 하나다.

## 적용 후 검증

1. 적용 전과 같은 명령으로 스냅샷을 수집하고 차이를 본다. 차이는 승인한 항목의 변화(외부 게시 포트 감소, 제거한 서비스)뿐이어야 한다.

```bash
scripts/collect-security-baseline.sh --label <라벨> --ssh <계정>@<호스트>
diff <적용 전>/snapshot.txt <적용 후>/snapshot.txt
```

2. diff 원본과 기준선·적용 후 스냅샷은 비공개 경로에 둔다. 이슈에는 통과 여부만 적는다.
3. 아래 "부정 시험"을 수행하고 결과를 비공개 노트에 적는다.
4. 제거한 관리 인터페이스 목록과 근거를 비공개 노트에 남긴다.

## 부정 시험

시험 출발지의 구체값은 공개하지 않는다. 각 시험의 출발지는 비공개 경로에 지정한다.

| 시험 | 출발지 | 기대 결과 |
|---|---|---|
| 인터넷 쪽에서 관리 접점에 직접 접근 | 인터넷 쪽 출발지(비공개 경로에 지정) | 연결이 닿지 않는다(거부 또는 무응답) |
| 허용 밖 출발지가 프록시 경로 접근 | 허용 밖 출발지(비공개 경로에 지정) | 프록시에서 거부된다 |
| 허용 출발지가 프록시 경로 접근 | 허용 출발지(비공개 경로에 지정) | 정상 로그인된다 |

응답 코드만 확인한다. 로그인 자격 증명을 명령줄에 넣지 않는다.

```bash
curl -sS -o /dev/null -w '%{http_code}\n' --max-time 5 <접점 주소>
```

호스트 자신에서 `curl`로 자기 프록시를 부르면 도커 게이트웨이 주소로 보여 허용 출발지로 오인된다. 부정 시험은 반드시 해당 출발지 장비에서 한다.

## Host Audit 기대치

#377이 읽을 기대치 목록이다. 점검은 읽기 전용이며 항목 ID와 통과 여부만 결과에 싣는다(주소·포트·시크릿 값 금지).

| ID | 기대치 | 합격 기준 |
|---|---|---|
| EXP-MGMT-1 | 관리용 웹 접점은 외부 대역(모든 주소)에 게시되지 않는다 | 컨테이너 게시 포트 중 관리 웹 접점이 모두 루프백 주소로만 바인드된다 |
| EXP-MGMT-2 | 관리 웹 접점의 외부 경로는 허용 출발지 기반 리버스 프록시 한 경로뿐이다 | 프록시 외에 모든 주소에서 청취하는 관리 웹 접점이 없다 |
| EXP-MGMT-3 | 제거 결정한 관리 인터페이스가 다시 올라오지 않는다 | 제거 목록의 서비스·게시 포트가 없다(목록 자체는 비공개 경로의 기대치 파일로 읽는다) |

주의: 노드 otelcol의 OTLP 수신기는 모든 주소 바인드가 설계된 예외다(ADR-0012). EXP-MGMT-1은 관리용 웹 접점에만 적용하고 이 예외를 퇴행으로 판정하지 않는다. overseer 스택 소속 접점은 이 티켓이 바꾸지 않으므로 변경 승인 전까지 기대치에서 제외한다.
