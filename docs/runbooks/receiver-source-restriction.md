# 로그·트랩 수신 접점 출발지 제한 런북

> 로그(syslog)와 트랩 수신 접점을 **호스트 방화벽 체인을 건드리지 않고** 애플리케이션 수준에서 제한한다(#370, 스펙 #364). 저장소에는 compose·수신기 설정이 없어 서버 작업은 이 런북으로만 수행하고, 항목마다 운영자 승인을 받는다. 공개 저장소라 IP·포트·방화벽 출발지·인증 문자열은 적지 않는다. 값은 모두 비공개 경로(`~/.local/share/infra-automation/sec-review-20261026/`)에 둔다.

## 1. 원칙

| 원칙 | 내용 |
|---|---|
| 허용 목록의 기준 | **수신기가 실제로 보는 출발지**다. 장비 관리 주소가 아니다. 장비가 다른 주소로 내보내거나(관리 인터페이스와 송신 인터페이스가 다름), 중간에서 주소가 바뀌거나(NAT, 사무실 S2S의 SNAT), 컨테이너 게시 경로(docker-proxy 등)를 지나면 수신기가 보는 값이 장비 목록과 달라진다. 허용 목록은 아래 3절의 수집 결과(수신기 쪽 관측)에서 만든다. |
| 방화벽 체인 불변 | firewalld·nft·iptables·DOCKER-USER를 변경하지 않는다. 제한은 syslog-ng 설정과 트랩 수신기 설정에서만 한다. 적용 전후 기준선 스냅샷의 `firewalld`, `nft-ruleset-stateless`, `iptables-docker-user` 구간 diff가 비어야 통과다. |
| 컨테이너 재생성 금지 | 설정은 읽어 들이게(reload)만 한다. compose `up`으로 컨테이너를 다시 만들지 않는다. 재시작이 필요하면 운영자 승인을 따로 받는다. |
| 항목별 승인 | 로그 제한과 트랩 인증은 각각 실현성 보고, 롤백 절차 기재, 운영자 승인 순으로 나눠 적용한다. |
| 값 비공개 | 이슈·PR·커밋에는 통과 여부만 적는다. 정상 출발지 목록, 인증 문자열, 거부 시험 출발지는 비공개 경로에만 둔다. |

## 2. 실현성 확인 보고 양식

적용 전에 이 양식을 채워 운영자에게 보고하고 승인받는다. 채운 보고서는 비공개 경로에 두고, 이슈에는 "가능/불가능, 방식, 승인 여부"만 적는다.

```text
## 실현성 보고 (로그 수신)
- 확인 일시 / 확인자:
- 수신기 컨테이너 이미지·버전:
- 사용자 설정 위치: (기본: 컨테이너의 사용자 설정 디렉터리, 메인 설정이 이 경로만 include한다 -- switch-syslog.md 2절)
- 확인 방법: 읽기 전용(실효 설정 전개 출력을 보고, 메인 설정의 log 경로 정의를 읽는다)
- 질문 1. 사용자 설정만으로 출발지 필터를 만들 수 있는가:
- 질문 2. 그 필터가 LibreNMS 저장 경로와 파일 보관 경로 **둘 다**에 적용되는가:
- 판정: A(전 경로 가능) / B(파일 보관 경로만 가능) / C(불가능)
- 방식: (예: 사용자 설정의 netmask 필터를 보관 경로에 연결)
- 남는 잔여 위험:
- 롤백 절차 위치: (5절)
- 운영자 승인: (일시, 승인자)

## 실현성 보고 (트랩 수신)
- 수신기와 설정 파일 위치:
- 현재 인증 설정: (인증 지시어 유무만. 값은 쓰지 않는다)
- 버전·프로토콜(v1/v2c/v3):
- 관측 기간과 수집 결과 위치: (3절)
- 관측되지 않은 장비(드물게 보내는 트랩 포함) 목록 위치:
- 판정: 가능/불가능, 방식:
- 롤백 절차 위치, 운영자 승인:
```

### 판정 기준 (로그 수신)

syslog-ng는 `log` 경로마다 독립적으로 메시지를 받는다. 사용자 설정에 필터 경로를 추가해도 메인 설정이 이미 정의한 경로는 막히지 않는다. 따라서 판정은 아래 셋 중 하나다.

| 판정 | 조건 | 의미 |
|---|---|---|
| A | 메인 설정이 수신 소스에 필터를 걸 수 있는 훅을 열어 두었다(또는 소스 정의 자체가 사용자 설정에서 덮인다) | 모든 경로에서 허용 밖 출발지가 폐기된다. |
| B | 파일 보관 경로가 사용자 설정이라 필터를 걸 수 있으나 LibreNMS 저장 경로는 메인 설정에 고정돼 있다 | 중앙 보관(OpenObserve)에는 허용 밖 로그가 들어오지 않지만 LibreNMS 화면에는 남는다. 잔여 위험으로 보고하고 승인받는다. |
| C | 어느 경로에도 필터를 걸 수 없다 | 애플리케이션 수준 제한 불가. 방화벽 체인 불변 원칙에서 벗어나는 대안은 이 티켓 범위가 아니므로 운영자에게 보고하고 중단한다. |

확인은 읽기 전용으로 한다. 컨테이너 안에서 설정을 전개해 보는 명령(`syslog-ng --preprocess-into`)과 메인 설정의 `log {}` 정의 읽기까지만 하고, 설정 파일을 바꾸거나 reload하지 않는다.

## 3. 적용 전 수집 (읽기 전용)

### 3.1 기준선 스냅샷

[기준선 수집기](security-baseline.md)로 적용 전 스냅샷을 남긴다. 적용 후에 **같은 명령**으로 다시 수집해 diff한다.

```bash
scripts/collect-security-baseline.sh --label <호스트> --ssh <user@host>
```

### 3.2 수신기가 실제로 보는 출발지와 인증 문자열

```bash
RECEIVER_TRAP_LOG_FILES="<수신기 로그 파일>" \
RECEIVER_TRAP_CONTAINERS="<수신기 컨테이너 이름>" \
RECEIVER_TRAP_CONF_FILES="<수신기 설정 파일>" \
scripts/collect-receiver-sources.sh --label <호스트> --ssh <user@host>
```

- 결과: `~/.local/share/infra-automation/sec-review-20261026/receiver-sources/<label>/<시각>/receiver-sources.txt`(0600). git 저장소 안 경로는 거부한다.
- 읽기 전용이다. 서버 상태를 바꾸는 명령이 없고(테스트가 강제), 로그 원문은 파이프로만 추출기에 넣고 디스크에 사본을 만들지 않는다.
- **인증 문자열은 값을 출력하지 않는다.** 길이와 해시 앞 12자만 싣고, 흔한 기본 문자열은 `default-string`으로 표시한다. 설정 파일의 인증 지시어도 문자열·passphrase를 가리고 허용 출발지(SOURCE)와 동작만 싣는다. 수집 결과에 시크릿 패턴이 있으면 폐기하고 실패한다.
- 구간별 의미:

| 구간 | 의미 | 허용 목록에 쓰는가 |
|---|---|---|
| `receiver-listeners` | 수신 포트를 듣는 소켓 | 아니오(상태 확인) |
| `conntrack-sources` | 커널이 본 **원래** 출발지(NAT 이전) | 아니오. 수신기 관측과 대조해 NAT·프록시 영향을 찾는 용도 |
| `syslog-sender-dirs` | 장비별 보관 디렉터리 이름 = 수신기가 실제로 본 송신 장비 | 예(로그) |
| `trap-sources-from-logs` | 수신기 로그에 찍힌 트랩 출발지 | 예(트랩) |
| `trap-auth-strings-masked` | 로그에서 본 인증 문자열의 길이·해시 | 설정과 해시를 비교해 같은 문자열인지만 본다 |
| `trap-auth-directives` | 설정의 인증 지시어와 허용 출발지 | 현재 상태 기록 |

- **수신기 관측과 conntrack 출발지가 다르면** 컨테이너 경로나 중간 장비에서 주소가 바뀐 것이다. 허용 목록은 **수신기가 본 값**으로 만들고, 어긋난 장비는 비공개 목록에 사유를 적는다. 허용 목록을 장비 관리 주소로 만들면 정상 장비가 폐기된다.
- **관측 기간**은 가장 드물게 보내는 장비의 주기보다 길어야 한다. 트랩은 이벤트가 있을 때만 오므로 짧게 보면 목록에서 빠진다. 빠진 장비는 인증 적용 후 알림이 조용히 사라지는 사고가 된다. 관측되지 않은 장비는 별도 목록을 만들어 운영자와 장비별로 확인한다.
- 수집 결과에서 정상 출발지 목록을 정리해 비공개 경로(`.../receiver-sources/approved-<호스트>.txt`)에 두는 것이 이 티켓의 선행 조건이다.

## 4. 적용 절차 (항목별 승인 후)

### 4.1 로그 수신 (실현성 판정 후)

1. 2절 양식을 채워 승인받는다. 판정이 C면 여기서 멈춘다.
2. 현재 사용자 설정 파일을 **include 대상이 아닌 이름**(확장자 `.conf`가 아닌 `.bak`)으로 비공개 백업한다.
3. 허용 출발지(3.2의 `syslog-sender-dirs`와 비공개 승인 목록)를 `netmask()`/`host()` 필터로 정의해 판정이 허용하는 경로에 연결한다. 값은 비공개 경로에서 가져오고 저장소에는 두지 않는다.
4. 설정 문법을 검사한다(`syslog-ng --syntax-only`). 실패하면 적용하지 않는다.
5. 컨테이너를 **재생성하지 않고** 설정만 다시 읽힌다(`syslog-ng-ctl reload`).
6. 6절 검증으로 넘어간다.

### 4.2 트랩 수신 인증

1. 3.2의 `trap-auth-strings-masked`와 `trap-auth-directives`를 비교해 장비별 (인증 문자열, 출발지) 쌍을 비공개 목록으로 확정한다. 인증 문자열의 실제 값은 장비 설정이나 OpenBao 등 시크릿 저장소에서 가져오고 이 런북·이슈에 옮기지 않는다.
2. 현재 설정 파일을 비공개 백업한다.
3. 수신기 설정에 인증 지시어(`authCommunity <동작> <문자열> <허용 출발지>`)를 장비 쌍마다 추가하고 기본 허용(`disableAuthorization`)을 끈다. 지시어를 추가하는 순간부터 목록에 없는 트랩은 폐기된다.
4. 설정은 재시작 없이 다시 읽힌다(HUP). 불가하면 운영자에게 컨테이너 재시작 승인을 따로 받는다(재생성 금지).
5. 6절 검증으로 넘어간다.

## 5. 롤백 절차 (적용 전에 기재, 승인에 포함)

| 대상 | 롤백 | 확인 |
|---|---|---|
| 로그 수신 | 비공개 백업한 사용자 설정을 원래 이름으로 복원하고 `syslog-ng-ctl reload` | 정상 장비 로그가 수신되고, 필터 추가 전 스냅샷과 diff가 비어 있다 |
| 트랩 수신 | 비공개 백업한 수신기 설정을 복원하고 HUP(또는 승인된 재시작) | 이전 관측 장비의 트랩이 다시 수신된다 |

- 롤백 트리거: 정상 장비의 로그·트랩이 한 대라도 끊기거나, 6절의 기준선 diff에서 예상 밖 변경이 보일 때. 의심되면 먼저 롤백하고 원인은 나중에 본다.
- 롤백 명령과 백업 위치는 적용 **전에** 비공개 노트에 적고 운영자가 확인한다.

## 6. 적용 후 검증

1. **스냅샷 diff**: 3.1과 같은 명령으로 다시 수집해 이전 것과 diff한다. 방화벽 구간(`firewalld`, `nft-ruleset-stateless`, `iptables-docker-user`)에 차이가 없어야 한다. 3.2도 다시 수집해 출발지 목록이 승인 목록 안에 있는지 본다. diff와 결과 원본은 비공개 경로에 남기고 이슈에는 통과 여부만 적는다.
2. **정상 장비별 확인**: 비공개 승인 목록의 장비마다 로그와 트랩이 계속 수신되는지 확인한다. 로그는 장비 디렉터리의 오늘 파일 갱신, 트랩은 수신기 로그의 새 항목으로 본다. 장비 한 대당 한 줄씩 비공개 노트에 체크한다.
3. **부정 시험(허용 밖 거부)**: 허용 밖 출발지에서 보낸 로그와 미인증 트랩이 거부·폐기되는지 확인한다.
   - 시험 출발지는 **비공개 경로에 지정**한 허용 밖 호스트다. 이 문서에는 적지 않는다.
   - 로그: 시험 출발지에서 표시 문자열이 있는 테스트 메시지를 보내고, 장비별 보관 파일과 중앙 보관(OpenObserve), LibreNMS 화면 어디에도 나타나지 않아야 한다(4.1 판정 B면 LibreNMS 화면은 잔여 위험으로 기록한 대로 남는다).
   - 트랩: 허용 출발지에서 **틀린 인증 문자열**로, 그리고 허용 밖 출발지에서 **맞는 문자열**로 시험 트랩을 보낸다. 둘 다 처리되지 않고 수신기 로그에 접근 설정 없음 등 폐기 기록이 남아야 한다.
   - 시험 메시지에는 표시 문자열 외에 실제 시크릿을 쓰지 않는다. 시험 후 흔적(시험 장비 디렉터리 등)은 승인받아 정리한다.
4. **수신 경로 끝단**: 중앙 보관(OpenObserve `system_logs`)에서 정상 장비의 최신 레코드 시각이 갱신되는지 본다([switch-syslog.md](switch-syslog.md) 3절).
5. 결과 통과 여부만 이슈에 적는다.

## 8. Host Audit 연계

#377이 퇴행 점검 항목 `EXP-RECV-1`~`EXP-RECV-3`으로 아래 기대치를 읽는다([Host Audit 명세 16절](../host_audit.md)). 점검 결과는 항목 ID와 통과 여부만 담고 출발지·문자열 값은 담지 않는다. 이 티켓은 Host Audit 코드를 수정하지 않는다.

- 로그 수신: 허용 출발지 필터가 켜져 있는가(수신 설정에 필터 정의가 있고 보관 경로에 연결돼 있는가)
- 트랩 수신: 인증 지시어가 있고 기본 허용이 꺼져 있는가, 기본 문자열(`default-string`)이 없는가
- 이미 Host Agents에 편입되어 수집기가 동작하는 서버가 있다(탐지 복구 런북 전제 3). 그 서버의 도달은 읽기 전용 조회로 확인한다. 편입되지 않은 서버는 Host Audit 점검 범위 밖이므로 이 절의 기대치를 수동 절차와 전후 스냅샷 diff로 확인한다.

## 9. 알려진 한계

- 같은 출발지에서 오는 위조 메시지는 막지 못한다. UDP syslog·트랩은 출발지 주소가 위조될 수 있어 이 제한은 우발적·외부 노출 차단용이다. 위조 방어는 망 수준(이 티켓 범위 밖)에서 본다.
- 트랩 v1/v2c 인증 문자열은 평문으로 전송된다. 목록 제한은 문자열 + 출발지의 이중 조건으로 위험을 줄일 뿐이다.
- 새 장비를 편입하면 허용 목록에도 추가해야 한다. 새 스위치·방화벽 편입 절차에 이 단계를 포함한다([switch-syslog.md](switch-syslog.md), [fortigate-syslog.md](fortigate-syslog.md)).
