# KISA 2026판 Unix 서버(U-01~U-67) 항목 구조 (이슈 #478, 지도 #477)

조사일 2026-11-16. 1차 자료: KISA 「주요정보통신기반시설 기술적 취약점 분석·평가 방법 상세가이드」 2026판(873쪽)과 2021판(756쪽) PDF 원문. 쪽 번호는 2026판은 **인쇄 쪽 = PDF 쪽(오프셋 0)**, 2021판은 **인쇄 쪽 = PDF 쪽 − 8**(PDF 13쪽이 인쇄 5쪽; 꼬리말 글리프로 확인)이다. 아래 "p."는 별도 표기가 없으면 2026판 인쇄 쪽이다. 텍스트는 pypdf로 추출해 항목별로 소제목을 기계 집계했다.

## 결론

1. **고정 소제목이 있고 67개 항목 모두 일관된다.** 항목마다 같은 순서로 `개요(점검 내용 / 점검 목적 / 보안 위협 / 참고)` -> `점검 대상 및 판단 기준(대상 / 판단 기준: 양호·취약)` -> `조치 방법` -> `조치 시 영향` -> `점검 및 조치 사례`가 나온다. 소제목 누락, 순서 뒤바뀜, 양호/취약 한쪽 누락은 0건이다.
2. **"조치 시 영향"은 가이드에 있다. 그러나 정량적 위험도·시급성 서술은 없다.** 영향 칸은 짧은 문장이고, 67개 중 50개가 정형 문구 "일반적인 경우 영향 없음"이다(U-01 p.12 등). 나머지 17개만 구체 영향(연동 구간 장애, 서비스 중단 가능성, 성능·용량 등)을 쓴다.
3. **위험·시급성에 해당하는 것은 두 가지뿐이다.** (a) 항목 제목 옆 `(상)/(중)/(하)` "항목 중요도"(상 40, 중 18, 하 9), (b) 개요의 "보안 위협"(공격 시나리오 서술). 중요도의 정의나 산정 기준을 설명하는 문장은 2026판 어디에도 없다(`중요도`·`위험도`·`시급` 검색으로 확인; 항목표 머리말 외 정의 없음). 조치 우선순위, 기한, 영향 등급(예: 서비스 중단 가능성 상/중/하)은 **우리가 정해야 한다**.
4. 가이드 스스로 판단 기준을 "권고"로 규정한다: 판단 기준은 "일반적으로 통용되는 권고 사항"이고 실제 양호·취약은 수행자가 정책·운용 상황을 고려해 최종 결정하며, 위험을 부담할 근거가 있으면 취약 판정을 양호로 볼 수 있다(PDF 2쪽 머리말, 인쇄 쪽 번호 없음).
5. **2021판과의 구조 차이는 크지 않다.** 소제목 틀은 거의 같고(2021판에도 `조치 시 영향` 칸이 72개 항목 전부에 있었다), 차이는 아래 "2021판 대비"에 정리한다.

## 항목 내부의 고정 소제목 (2026판)

U-01(p.12-14) 기준 원문 순서:

- 머리줄: `U-01(상) UNIX > 1. 계정 관리` + 항목명
- `개요` 아래 `점검 내용`, `점검 목적`, `보안 위협`, `참고`
- `점검 대상 및 판단 기준` 아래 `대상`, `판단 기준`(`양호 :` / `취약 :`)
- `조치 방법`(한두 문장의 요지)
- `조치 시 영향`
- `점검 및 조치 사례`: OS별(SOLARIS, LINUX, AIX, HP-UX) 소제목 아래 `Step 1)`, `Step 2)`... 순서의 파일 경로·설정값·명령

## 일관성 예외 목록

- **"참고" 칸 비어 있음(`-`)**: U-06(p.29), 08, 31, 33, 45(p.105), 53, 61, 65, 67. 소제목은 있되 내용이 없다.
- **조치 시 영향의 개별 서술 17건**: U-02, 03, 04, 05, 06, 10, 12, 19, 23, 28, 41, 45, 49, 50, 56, 57, 66. 이 중 U-05는 "해당 계정에 관리자 권한이 필요하지 않으면 일반적으로 영향 없음", U-50은 "...정상적으로 등록하였다면 일반적으로 영향 없음"으로 사실상 표준문구의 변형이다. U-03·U-04는 HP-UX Trusted Mode 전환 영향을 쓴다.
- **OS 범위**: 사례 절은 전 항목에 SOLARIS·LINUX·AIX·HP-UX가 있다. 배포판명은 일부에만 나온다: Debian U-02, 03, 13, 60, 61 / Ubuntu·CentOS는 U-01 한 항목(p.13, "CentOS 8, Ubuntu 20.04 이상부터 /etc/securetty 없음" 주석). Rocky, RHEL 등 개별 배포판 구분은 없다.
- **쪽 수 편차**: 항목 길이가 1쪽(U-07 p.31-32)에서 9쪽(U-62 p.150-159)까지 다르다. 소제목은 같고 사례 절 분량만 다르다.
- U-67 이후 같은 PDF에 Windows 장(p.172~)이 이어진다. 본 조사는 Unix 장(p.12~171)만 대상으로 했다.

## 대표 항목 원문 구조

(원문은 추출 텍스트에서 소제목 단위로 끊어 옮긴 것. 발췌는 짧게.)

**U-01 root 계정 원격 접속 제한 (상), p.12-14**
- 점검 목적: 관리자 계정 탈취로 인한 시스템 장악을 방지...
- 보안 위협: root 계정은 운영체제의 모든 기능을 설정 및 변경이 가능하여... 시스템 장악 및 각종 공격으로... root 계정 사용 불가 위험이 존재함
- 판단 기준: 양호 = 원격터미널 서비스를 사용하지 않거나 root 직접 접속을 차단한 경우 / 취약 = 허용한 경우
- 조치 방법: 원격 접속 시 root 계정으로 접속할 수 없도록 파일 내용 설정
- 조치 시 영향: 일반적인 경우 영향 없음
- 사례: SOLARIS/LINUX/AIX/HP-UX 각각 `[Telnet]`, `[SSH]` 아래 `Step 1)` (예: `/etc/ssh/sshd_config` 의 `PermitRootLogin No`)

**U-02 비밀번호 관리정책 설정 (상), p.15-21**
- 조치 방법: ...영문, 숫자, 특수문자를 포함하여 최소 8자리 이상 및 최소 사용 기간 1일, 최대 사용 기간 90일, 최근 비밀번호 기억 4회 이상으로 설정
- 조치 시 영향: 비밀번호 변경 시 Web, WAS, DB 연동 구간에서 문제가 발생할 수 있으므로 연동 구간에 미칠 수 있는 영향을 고려하여 적용 필요
- 사례: OS별(+Debian) `Step` 아래 설정값(예: SOLARIS `/etc/default/passwd`의 `HISTORY=4`, `PASSLENGTH=8`...)

**U-07 불필요한 계정 제거 (하), p.31-32**
- 사례가 OS별이 아니라 "SOLARIS, LINUX, AIX, HP-UX" 공통 한 묶음이고, `[/etc/passwd 파일을 이용하여 점검]`, `[log를 이용하여 점검]`처럼 점검 방식별로 나뉜다(`userdel <사용자 이름>`, AIX는 `rmuser`).
- 보안 위협 끝에 "(퇴직, 전직, 휴직 등의 사유 발생 시 즉시 권한을 회수하는 것을 권고함)" 같은 운영 권고가 섞여 있다.

**U-45 메일 서비스 버전 점검 (상), p.105-111**
- 참고: `-`(비어 있음)
- 조치 방법: 불릿 두 개(미사용 시 서비스 중지·비활성화 / 사용 시 패치 관리 정책 수립)
- 조치 시 영향: 패치 적용 시 시스템 및 서비스의 영향 정도를 충분히 고려해야 함
- 사례: Sendmail / Postfix / Exim 별로 `[사용하는 경우]`, `[사용하지 않는 경우]` 하위 구분이 OS마다 반복

**U-66 정책에 따른 시스템 로깅 설정 (중), p.166-171**
- 참고: 감사 설정이 너무 높으면 불필요한 항목이 많이 기록되어 중요 항목과 혼동... 성능에도 심각한 영향
- 조치 시 영향: 아래 제시한 모든 로그를 설정할 경우, 시스템 성능과 로그 저장에 따른 서버 용량 부족 문제가 발생할 수 있으므로 시스템 운영 환경과 특성을 고려하여 적용
- 사례: `[syslog]`/`[rsyslog]` 별 설정 파일과 로그-경로 표 (`*.info;mail.none;authpriv.none;cron.none` -> `/var/log/messages` 등)

## 2021판 대비

2021판 확인 범위: 항목 본문 구조(인쇄 쪽 5~142, PDF 13~150).

| 구분 | 2021판 | 2026판 |
|---|---|---|
| 항목 수·코드 | U-01~U-72(72개) | U-01~U-67(67개). 항목 번호와 순서가 재배열됨(예: 2021 U-01 root 원격 접속 제한 -> 2026 U-01 동일, 2021 U-42 패치 -> 2026 U-64) |

| 머리줄 | `U-01 (상) 1. 계정관리 > 1.1 root 계정 원격접속 제한` (소분류 번호 1.1 포함) | `U-01(상) UNIX > 1. 계정 관리` + 항목명 (소분류 번호 없음) |
| 개요 소제목 | `취약점 개요` 아래 `점검내용`, `점검목적`, `보안위협`, `참고`(79회 출현) | `개요` 아래 `점검 내용`, `점검 목적`, `보안 위협`, `참고`(띄어쓰기 변경, 참고는 67개 전부) |
| 판단 | `점검대상 및 판단기준` / `양호 :` `취약 :` 72/72 | 동일(띄어쓰기만 다름) |
| 조치 방법 | `조치방법` 72/72 | `조치 방법` 67/67 |
| 조치 시 영향 | `조치 시 영향` 칸이 있고 72/72(줄바꿈으로 "조치 시 / 영향"으로 갈라져 단순 검색에 안 잡힘). 표준문구 45개 | 67/67. 표준문구 50개 |
| 점검 vs 조치 사례 | `점검 및 조치사례` 아래에 **두 부분**: `OS별 점검 파일 위치 및 점검 방법`(67개, `#cat ...` 점검 명령과 양호 설정 예)과 `보안설정방법`(57개, `Step` + `(수정 전)/(수정 후)` 62곳) | `Step 1)...`로 **통합**. `(수정 전)/(수정 후)` 표기가 없고, 점검 명령(`# cat`)은 17개 항목에서만 남음 |
| 대상 OS | SOLARIS, LINUX, AIX, HP-UX | 동일. Debian(5개), Ubuntu·CentOS(U-01 주석)만 추가 언급 |

즉 구조는 거의 승계되었고, 가장 눈에 띄는 변화는 "점검 방법"과 "조치 방법" 사례를 따로 두던 2021판의 이중 구성이 2026판에서 Step 단위 한 덩어리로 합쳐진 점이다. 우리가 자동 점검/조치 항목으로 옮길 때는 "점검 판정 기준 = 판단 기준(양호/취약)", "조치 = 사례의 Step", "영향 = 조치 시 영향(대부분 정형문구)"으로 대응시키되, 영향의 등급·시급성은 가이드가 주지 않으므로 별도 기준이 필요하다.

## 한계

- 표의 소제목 집계는 PDF 텍스트 추출 결과 기준이다. 표·그림 안의 글자나 페이지 경계의 잘림은 확인하지 못했다. 대표 항목 발췌는 원문과 대조했다.
- 2021판은 항목 구조와 소제목 출현 횟수만 집계했고, 항목 대응표(2021 번호 -> 2026 번호)는 만들지 않았다. 필요하면 후속 조사.
- 2026판 사례 절의 OS별 명령(예: Rocky/RHEL 계열 명령)은 이 조사 범위 밖이다.
